# 从者自动获取的识别范围（0.4.2）

识别依赖 Atlas 结构化字段，不按从者名、技能名或说明文字关键词猜测。只要新从者仍采用当前支持的数据结构，通常无需改程序。

## 双宝具
优先读取主宝具的 tdTypeChangeIDs，对应候选必须存在于返回的宝具列表；可以识别同色同类型的显式切换。没有该关联时按卡色和单体/群体/辅助类型分组，并在组内选择优先级较高的版本。超过两种候选会保留全部候选供设置中选择，计算页仍使用宝具1/2。

限制：没有显式关联、又同色同类型的不同宝具，可能被合并为一个；使用新函数或新字段定义的切换不保证自动识别。未直接列出的隐藏候选不会自动推导。

## 变身
扫描主动技能、宝具和职阶被动中直接作用于自身的 transformServant，从 svals.Value 取得目标 ID，并将形态加入下载队列；因此目标不在常规索引中也可获取。新形态还必须通过目前支持的从者类型、职阶和数据校验。

限制：嵌套触发中的变身、用新函数或其他字段表示的形态关系未必识别。已有 ID 按约定跳过详情下载，所以旧从者日后新增宝具/变身/被动不会自动更新，需手动编辑，或备份后删除该记录再重新获取。

## 无条件与有条件混合被动
逐函数、逐 buff 判断。已支持的直接、无限期、100%概率且无次数/场地/状态限制的数值效果会录入；另一个函数里的条件部分会被排除。现有 Kingprotea 的常驻3星/水边2星即采用这种处理。

限制：若 Atlas 将条件放在整个技能的脚本上，脚本会保守排除该技能下的数值效果，无法仅凭文字拆出常态部分。新 buff 类型、新 script 参数或新的数值编码也不能保证识别。部分排除项只出现在“数据识别记录”中，不一定触发需核对统计。

## 验证
现有真实数据测试覆盖原初之一、逆光EX、Kingprotea混合被动等。额外用不存在于内置库的新ID构造了显式双宝具、颜色分组、混合被动与变身队列样例，验证识别依赖结构。模拟样例不能保证未来官方的所有新机制都会兼容。

结论：通常能识别沿用现有结构的新从者；不能承诺所有未来特殊从者百分之百自动识别。首次录入特殊机制从者后，应查看宝具候选、变身形态和数据识别记录。
